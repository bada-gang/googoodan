# 구구 마을

초등학교 2학년 곱셈구구 성장형 게임. 태블릿 웹브라우저(가로 화면) 전용.

> 곱셈 문제를 풀어야 해서 게임을 하는 것이 아니라,
> **내 집과 농장을 키우다 보니 자연스럽게 곱셈구구를 계속 풀게 되는 것**이 목표다.

---

## 실행

```bash
npm install
```

```bash
npm run dev
```

```bash
npm run build
```

`npm run dev` 는 `--host` 로 열리므로, 같은 네트워크의 태블릿에서
`http://<PC의 IP>:5173` 으로 접속해 실제 기기에서 테스트할 수 있다.

## 지금까지 만들어진 것 (프론트엔드)

Phase 1 ~ 9 가 동작한다. 서버 저장(Firebase)과 선생님 화면까지 붙어 있고,
설정이 없거나 서버가 막히면 이 기기에만 저장한다.

- 이름/캐릭터 선택 → 구구단 선택 → 게임 (명세 8~12)
- 구구단 선택 화면에서 캐릭터 바꾸기 (학생이 직접)
- 2D 횡스크롤 월드 3곳: 우리 마을(집·농장·동물 우리) / 집 내부 / 시장
- 태블릿 터치 조작 (이동 버튼, 상황별 행동 버튼, 48px 이상 터치 영역)
- 곱셈구구 출제기 — 균형 출제 70% + 취약 문제 30%, 오답 복습, 인접 곱셈 오답 선택지
- 씨앗 구입 → 심기(물 사용) → 5단계 성장 → 수확 → 판매 → 돈
- 가구·장식 구입 → 배치·이동·회전·회수, 벽지/바닥 교체
- 동물 구입 → 먹이 주기(먹이 사용) → 생산물 수확 → 판매
- 미니게임 "열매 받기 게임"(접속당 1회) → 랜덤 상자 → 집에서 열기
- 레벨·경험치·콘텐츠 해금
- 자동 저장 / 다시 접속 시 이어하기 (서버 또는 이 기기)
- 선생님 화면 — 학급 학습 기록 보기, 명단 등록, 기록 초기화

## 기술 구성

```
Vite + React 19 + TypeScript + Tailwind CSS 4 + Phaser 3 + Zustand
```

| 영역 | 담당 |
| --- | --- |
| Phaser 3 | 게임 월드, 캐릭터, 나무, 동물, 건물, 카메라, 애니메이션, 파티클, 미니게임 |
| React 19 | 시작 화면, HUD, 문제 팝업, 상점·가방·꾸미기 오버레이 |
| Tailwind CSS | React UI 스타일만 |
| Zustand | 게임 상태 (Phaser 와 React 가 같은 스토어를 본다) |

## 핵심 설계

### Phaser ↔ React 통신 (명세 71)

Scene 이 React 컴포넌트를 직접 만지지 않는다. `src/bridge/events.ts` 의 계약만 오간다.

```
Phaser: HARVEST 행동 → math:request
React : 문제 생성 → 팝업 → 정답 판정 → 학습 기록 → math:result
Phaser: 수확 실행 + 연출
```

문제를 요구하는 모든 흐름은 `src/ui/mathFlow.ts` 의 `askMath()` 한 곳을 지난다.
Phaser 에서 오든 상점 화면에서 오든 출제·판정·기록 규칙이 같다.

### 문제를 내는 곳과 내지 않는 곳 (명세 78)

| 문제를 낸다 | 문제를 내지 않는다 |
| --- | --- |
| 씨앗 심기 · 물 주기 · 수확 | 이동 · 탐색 · 집 구경 |
| 먹이 주기 · 생산물 받기 | 가구 배치 · 이동 · 회전 · 회수 |
| 구입 · 판매 · 랜덤 상자 | 벽지/바닥 바꾸기 · 가방 열기 |

### 아트 에셋 (명세 62~65)

게임 로직에는 파일 경로가 없다. `src/config/assets.ts` 의 `ASSETS` 키만 쓴다.
지금은 실제 아트가 없어 `src/game/placeholder/` 가 Canvas 로 임시 그림을 만든다.
실제 아트 교체 방법은 [ART_DIRECTION.md](ART_DIRECTION.md) 14번 항목 참고.

### 화면 배율

게임과 UI 모두 논리 해상도 1280×800 으로 그린다.
Phaser 는 Scale Manager(FIT)로, React UI 는 `LogicalLayer` 의 CSS transform 으로
같은 비율로 확대·축소되므로 어떤 태블릿에서도 배치가 어긋나지 않는다.

## 서버 저장 (Firebase)

**설정하지 않아도 게임은 돌아간다.** 키가 없으면 이 기기(localStorage)에만 저장한다.
설정 화면 아래쪽에서 지금 어디에 저장 중인지 볼 수 있다.

### 켜는 방법

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트 생성
2. **Authentication → 로그인 방법 → 익명** 사용 설정
3. **Firestore Database** 만들기 (프로덕션 모드)
4. **프로젝트 설정 → 내 앱 → 웹 앱 추가** → 표시된 설정값 복사
5. `.env.example` 을 `.env.local` 로 복사하고 값 채우기
6. 보안 규칙 적용

```bash
cp .env.example .env.local
```

규칙은 `firestore.rules` 에 있다. 콘솔의 **Firestore → 규칙** 에 붙여 넣거나,
한 번 로그인해 두면 명령 한 줄로 올릴 수 있다.

```bash
npx firebase login
```

```bash
npx firebase deploy --only firestore:rules
```

> 규칙을 올리지 않으면 프로덕션 모드 기본값이 모든 접근을 막는다.
> 이때 게임은 시작할 때 그 사실을 확인하고 조용히 이 기기 저장으로 넘어간다
> (콘솔에 `[data] Firebase 연결 실패` 가 뜬다).

### 설계

- **학생은 로그인하지 않는다.** 앱이 익명 인증으로 자동 로그인하고, 규칙은
  "로그인한 기기인지"만 확인한다. 주소만 아는 외부인의 접근을 막는 용도다.
- **데이터는 익명 UID 가 아니라 playerId 에 묶인다.** 그래서 태블릿을 바꿔도
  이름만 고르면 이어서 할 수 있다.
- **오프라인에서도 계속 플레이된다.** Firestore 오프라인 캐시를 켜 두었고,
  Wi-Fi 가 끊긴 동안의 저장은 큐에 쌓였다가 다시 연결되면 자동으로 올라간다.
- **연결에 실패하면 이 기기 저장으로 넘어간다.** 수업이 멈추지 않게 하려는 것이다.
  시작할 때 규칙이 읽기를 허용하는지 한 번 확인하고, 응답이 10초 안에 없으면 기다리지 않는다.
  수업 도중 서버가 막혀도 (`src/data/resilient.ts`) 그 자리에서 이 기기 저장으로 내려간다.
- **저장본을 못 읽은 판은 저장하지 않는다.** 새 게임 상태로 학생의 기존 진행도를
  덮어쓰는 것이 못 읽는 것보다 나쁘기 때문이다.

```
players/{playerId}   이름 · 캐릭터 · 마지막 접속
saves/{playerId}     진행도 (돈·농장·동물·가방·집)
stats/{playerId}     학습 통계 (단별 · 문제별 누적)
```

> 참고: 농장·동물·인벤토리는 항상 같은 시점에 함께 저장되므로(자동 저장)
> 명세의 `FarmRepository` / `AnimalRepository` / `InventoryRepository` 를 나누지 않고
> 하나의 `GameStateRepository` 애그리게이트로 다뤘다.

## 선생님 화면 (명세 73)

`/teacher.html` — **학생 게임과 분리된 페이지**다. 그래서 교사 화면에는 Phaser 가 실리지 않고,
학생 번들에도 교사 화면 코드가 섞이지 않는다.

```bash
npm run dev
```

연 다음 `http://localhost:5173/teacher.html` 로 들어간다.

### 보이는 것

| 반 전체 | 학생별 |
| --- | --- |
| 학생 수 · 문제 푼 학생 수 | 레벨 · 푼 문제 수 · 전체 정답률 |
| 반 단별 정답률 (2~9단) | 단별 정답률 (2~9단) |
| 반에서 자주 틀리는 문제 | 자주 틀리는 문제 · 가장 약한 단 |
| | 마지막 플레이 시각 |

표의 줄을 누르면 그 학생의 상세가 열린다.

캐릭터 이름은 목록에 넣지 않는다 — 선생님에게는 군더더기다.
**같은 이름이 둘 이상일 때만** 이름 옆에 캐릭터를 붙인다. 그때는 이름만으로 구별되지 않기 때문이다. (명세 10)

### 관리

- **학생 추가** — 명단을 통째로 붙여 넣는다. 줄바꿈이나 쉼표로 나누고, `1.` `2)` 같은
  번호는 알아서 떼어 낸다. 캐릭터는 자동 배정하되 **이름이 겹치면 서로 다른 캐릭터**를 준다.
  학생이 자기 이름을 찾을 때 구별되는 건 이름과 캐릭터 조합뿐이기 때문이다. (명세 10)
- **기록 초기화** — 진행도와 학습 기록만 지운다. 이름과 캐릭터는 남는다.
- **학생 지우기** — 통째로 지운다. 되돌릴 수 없다.

되돌릴 수 없는 두 버튼은 무엇이 지워지는지 글로 보여 준 뒤 한 번 더 묻는다.

### 암호

`.env.local` 의 `VITE_TEACHER_PASSCODE` 에 적는다. 비워 두면 암호 없이 열린다.

```
VITE_TEACHER_PASSCODE=원하는암호
```

> ⚠ **이건 보안이 아니다.** 암호는 브라우저로 내려가는 파일 안에 그대로 들어 있고,
> Firestore 규칙은 여전히 "익명 로그인한 기기"면 통과시킨다.
> 학생이 주소를 눌러 우연히 들어오는 것을 막는 정도로만 쓴다.

### 집계 규칙

숫자를 만드는 코드는 `src/teacher/summary.ts` 한 곳에 있다 (화면 컴포넌트에서 계산하지 않는다).

- **아직 안 푼 단은 `–`** 로 둔다. 0% 로 보이면 "다 틀렸다"로 오해한다.
- **자주 틀리는 문제는 틀린 횟수 순**이다. 정답률 순으로 하면 한 번 풀고 틀린 문제가 맨 위로 온다.
- **가장 약한 단은 3문제 이상 푼 단**에서만 고른다.
- **반 정답률은 학생별 정답률의 평균이 아니라 문제 수로 합친다.** 두 문제 푼 학생이
  반 평균을 흔들면 안 된다.

## 배포 (Netlify)

`netlify.toml` 에 빌드 명령(`npm run build`)과 결과 폴더(`dist`)가 적혀 있어
저장소를 연결하면 그대로 빌드된다.

- 학생 화면 — `https://<사이트>/`
- 선생님 화면 — `https://<사이트>/teacher`

### 환경변수를 반드시 넣어야 한다

`.env.local` 은 git 에 올라가지 않으므로 Netlify 는 그 값을 모른다.
**사이트 설정 → Environment variables** 에 아래 일곱 개를 넣는다.

```
VITE_FIREBASE_API_KEY
VITE_FIREBASE_AUTH_DOMAIN
VITE_FIREBASE_PROJECT_ID
VITE_FIREBASE_STORAGE_BUCKET
VITE_FIREBASE_MESSAGING_SENDER_ID
VITE_FIREBASE_APP_ID
VITE_TEACHER_PASSCODE
```

안 넣어도 빌드는 되지만 서버 저장이 꺼져서 태블릿마다 따로 저장된다.

> ⚠ `VITE_` 환경변수는 빌드할 때 자바스크립트 번들에 그대로 박힌다.
> 방문자가 개발자도구로 볼 수 있고, 이건 어느 호스팅을 쓰든 마찬가지다.
> Firebase 웹 설정값은 원래 공개를 전제로 한 값이고,
> 실제 방어선은 `firestore.rules` 다.
